Блокировщик рекламы для Chrome (Manifest V3), который **просто работает**:
ставится, и настраивать ничего не нужно. Убирает рекламу на всех сайтах, а на
русских сайтах — Авито, Яндексе, Яндекс.Играх — доводит результат до чистой
страницы без пустых мест.

Раньше назывался **Yandex Games AdBlocker** и умел только Яндекс.Игры — это
по-прежнему часть Cleathernet (см. [Яндекс.Игры](#почему-обычный-adblock-оставляет-дыру)).

## Возможности

- **Реклама на всех сайтах** — движок [uBO Lite](https://github.com/uBlockOrigin/uBOL-home)
  со списками EasyList, EasyPrivacy и RU AdList. RU AdList включён всегда, а не
  только в браузере на русском.
- **Назойливое** — уведомления о cookie и всплывающие окна поверх страницы.
  В настройках можно добавить чаты поддержки, кнопки соцсетей и другое.
- **Яндекс.Игры** — баннеры убираются, а игра растягивается на их место;
  рекламные окна платформы закрываются сами.
- **Выключить на сайте одной кнопкой** — если сайт сломался. Наши правки
  убираются сразу, без перезагрузки страницы.
- **Незаметность** — режим движка выбран так, чтобы приманки детекторов
  блокировщиков оставались нетронутыми; наш код не оставляет следов на странице.
- **Без телеметрии.** Расширение обращается только к GitHub — узнать, не вышла
  ли новая версия.

Авито и Яндекс.Поиск — в работе: реклама там хитрее, общие списки оставляют
пустые места, и их мы дочищаем отдельно.

## Установка

Расширение ставится из архива, без магазина. Это займёт пару минут, и
делается один раз.

### Chrome

1. **Скачайте архив:** [cleathernet.zip](https://github.com/BonpocOP/YandexAdBlocker/releases/latest/download/cleathernet.zip).
2. **Распакуйте его в постоянную папку**, например `Документы\Cleathernet`.
   Не удаляйте эту папку потом: расширение работает прямо из неё.
3. Откройте в адресной строке `chrome://extensions`.
4. Включите **«Режим разработчика»** — переключатель в правом верхнем углу.
5. Нажмите **«Загрузить распакованное расширение»** и выберите папку из
   шага 2 — ту, внутри которой лежит файл `manifest.json`.
6. Откроется страница «Cleathernet установлен и уже работает».

Если у вас стоит **Yandex Games AdBlocker** — удалите его: всё, что он умел,
теперь внутри Cleathernet, а вдвоём они мешают друг другу на Яндекс.Играх.

Чтобы значок был всегда под рукой, нажмите на пазл справа от адресной строки
и закрепите расширение кнопкой-булавкой.

### Яндекс.Браузер, Edge, Opera

Всё то же самое, меняется только адрес страницы расширений:

| Браузер | Адрес | Где «Режим разработчика» |
|---|---|---|
| Яндекс.Браузер | `browser://extensions` | справа вверху |
| Edge | `edge://extensions` | в левой панели |
| Opera | `opera://extensions` | справа вверху |

### Обновление

Когда выходит новая версия, в меню расширения появляется ссылка на неё.

1. Скачайте новый архив по той же [ссылке](https://github.com/BonpocOP/YandexAdBlocker/releases/latest/download/cleathernet.zip).
2. Распакуйте его **в ту же папку**, заменив файлы.
3. На странице расширений нажмите на карточке кнопку обновления ↻.

Настройки сохранятся: у расширения постоянный номер, и браузер узнаёт его
даже в другой папке.

### Если что-то не так

- **Сайт работает неправильно.** Нажмите на значок Cleathernet и выключите
  его на этом сайте. Значок станет серым.
- **Реклама осталась.** В меню расширения → **«Сообщить о проблеме»** →
  **«Скопировать отчёт»** и пришлите его в
  [Issues](https://github.com/BonpocOP/YandexAdBlocker/issues). В отчёте —
  адрес страницы, настройки расширения и, на Яндекс.Играх, разметка страницы
  игры; ни логинов, ни истории.
- **Браузер предлагает отключить расширения в режиме разработчика.** Закройте
  предупреждение, ничего не отключая: так браузер ведёт себя со всеми
  расширениями, установленными не из магазина.
- **Расширение пропало после перезапуска.** Скорее всего, папку удалили или
  переместили. Повторите установку и не трогайте папку.

### Из исходников

Движок uBO Lite в репозитории не хранится: сборка скачивает закреплённую
версию (`vendor/ubol.json`, сверка по SHA-256) и кладёт наш код сверху.

```
cd dev
npm install
node build-extension.mjs     # → build/extension
```

На пятом шаге установки выбирается папка `build/extension`.

## Почему обычный AdBlock оставляет дыру

uBlock и AdBlock умеют одно — спрятать узел (`display: none`). На странице игры
этого мало, потому что место под рекламу вычитается **инлайн-стилем на обёртке
фрейма**:

```html
<div class="wAxTIv38TmZAY" style="width: calc(99.99% - 315px); height: calc(99.99% - 107px)">
    <iframe id="game-frame"></iframe>
</div>
```

`315px` — боковой блок, `107px` — нижний sticky-баннер. Баннер убран,
а вычитание осталось — вот и пустое поле. Вдобавок игра живёт в `<iframe>`, и её
канвас перерисовывается только после события `resize`.

Расширение делает все три шага: **скрыть → снять резерв → заставить
пересчитать размер**.

## Как это работает

| Файл | Мир | Роль |
|---|---|---|
| `src/blocker.css` | страница | Растягивает фрейм игры; прячет рекламу до старта JS через `visibility`, чтобы её высота осталась измеримой |
| `src/content/` | isolated | Снимает резерв места, скрывает рекламные блоки, следит за DOM через `MutationObserver` |
| `src/sdk-hook.js` | MAIN | Подменяет `ysdk.adv.showFullscreenAdv` / `showRewardedVideo` |
| `popup/` | — | Тумблеры, счётчик, кнопка отчёта |

Content-script разложен по зонам ответственности и подключается в `manifest.json`
**строго в этом порядке**:

| Файл | Роль |
|---|---|
| `config.js` | Настройки по умолчанию, имена атрибутов, все зацепки за разметку |
| `state.js` | Состояние, счётчики, обработка обрыва контекста расширения |
| `dom.js` | Измерения, обратимая правка стилей, скрытие узлов |
| `layout.js` | Снятие резерва места, растягивание фрейма, центрирование |
| `ui.js` | Плашка, карточка с отсчётом, возврат фокуса в игру |
| `modals.js` | Распознавание и закрытие рекламных модалов |
| `scan.js` | Проходы по странице, наблюдатели, применение настроек |
| `report.js` | Диагностический отчёт |
| `main.js` | Связь с попапом и чтение настроек |

Отдельных модулей ES здесь нет намеренно: content-script'ы MV3 — обычные
скрипты, и перечисленные в одном `js` файлы делят **общую область видимости**
изолированного мира. Объявление из `dom.js` видно в `scan.js` напрямую, без
импортов и без объекта-неймспейса. Цена — порядок в `manifest.json` имеет
значение, а имена верхнего уровня обязаны не пересекаться.

### Растягивание игры

Класс обёртки хешированный (`wAxTIv38TmZAY`) и меняется между сборками, поэтому
цепляемся **структурно**:

```css
div:has(> iframe#game-frame),
iframe#game-frame { width: 100% !important; height: 100% !important; }
```

`!important` в таблице стилей перебивает инлайн-стиль, так что размер держится
даже после того, как скрипт страницы пересчитает `calc` заново. `fixGameShell()`
в `content.js` дублирует правило на случай, если резерв окажется выше по дереву,
а отдельный наблюдатель за атрибутом `style` возвращает размер, если разметка
перепишет его целиком. Событие `resize` троттлится: без ограничителя страница и
расширение уходят в бесконечную перепалку пересчётов.

### Когда игра не занимает освободившееся место

Растягивание работает не одинаково во всех играх. Одни пересчитывают канвас по
новому размеру и занимают место целиком; другие держат свои пропорции, и игра
оказывается в рамке, смещённой от центра.

Починить это «правильно» со стороны страницы нельзя: канвас живёт в
**кросс-доменном** `<iframe>`, его геометрию не измерить и не сдвинуть. Поэтому
сделано три вещи.

**Поздний пересчёт.** Игра снимает мерку, когда загрузится, — заметно позже,
чем отрабатывает расширение. Если к тому моменту она уже посчитала размер по
старому, ни один ранний пересчёт до неё не дошёл. `resize` пинается ещё раз по
событию `load` фрейма и затем с задержками 1.5 и 3.5 секунды.

**Остаток колонки убирается из потока.** Боковой блок лежит в собственной
обёртке, и она остаётся на месте даже после того, как содержимое скрыто — в
отчёте это 315×948 на `x = 1597`, ровно поверх правого края растянутой игры.
Полоса невидима, но занимает место и перехватывает клики. Ищется по
измерениям, а не по классу (он хеширован): родитель той же ширины, что и
скрытый блок, узкий по меркам экрана и **без фрейма игры внутри** — последнее
условие обязательно, иначе под нож попала бы обёртка самой игры.

**Тумблер на конкретную игру.** Если игра всё равно смотрится в рамке не по
центру, в попапе выключается «Растягивать по ширине». Высота растягивается
по-прежнему — место из-под нижнего баннера игре нужно в любом случае, на
пропорции это не влияет. Ширина возвращается к исходной, а освободившиеся
315px делятся поровну.

Поровну их делит `centerGameShell()` — **числом, а не `margin: auto`**. Авто-поля
в этой разметке не срабатывают: игра прижимается к краю, и вся пустота
собирается с одной стороны.

```
   растягивание вкл.            растягивание выкл.,
                                 авто-поля не сработали
┌─────┬──────────────┐      ┌──────────────┬─────┐
│пусто│     игра     │      │     игра     │пусто│
└─────┴──────────────┘      └──────────────┴─────┘

              стало: зазор посчитан и поделён
           ┌──────┬────────────┬──────┐
           │ пусто│    игра    │пусто │
           └──────┴────────────┴──────┘
```

Зазор считается как разница ширины родителя и обёртки, половина ставится
отступом. Абсолютно спозиционированную обёртку отступы не двигают — для неё
ставится `left`, то есть то же свойство, которым её держит страница. Если
обёртка уже по центру, правка не повторяется: иначе выйдет перепалка со
скриптом страницы, который пересчитывает свои размеры в ответ.

Настройка помнится для каждой игры отдельно — по числовому id из адреса
`/games/app/<slug>-<id>`: slug Яндекс меняет вместе с названием, а id остаётся.
Список лежит в `chrome.storage.sync`, то есть переезжает вместе с профилем.

### Если баннер всё-таки найден

`content.js` опирается на **измерения, а не на имена классов**:

- запоминает высоту баннера `H` до скрытия;
- в цепочке родителей обнуляет всё, что равно `H`: `padding-bottom`,
  `margin-bottom`, `calc(...)` в инлайн-стилях, px-трек в `grid-template-rows`,
  CSS-переменные с «adv/ads/banner» в имени;
- идёт от `<iframe>` вверх и растягивает элемент, который ровно на `H` ниже
  своего родителя.

### Реклама через SDK и почему нужен широкий доступ

Игра открывается в `<iframe>`, который **захостен на домене разработчика**, а не
у Яндекса:

```
https://ladacha.labsystech.ru/publish/html5/index-ru.html
    ?sdk=https%3A%2F%2Fgames.s3.yandex.net%2Fsdk%2F_%2Fv2.js
    &sdk_origin=sdk.games.s3.yandex.net
```

SDK подгружается с серверов Яндекса, но сама страница к ним отношения не имеет,
и у каждой игры домен свой — перечислить их в `matches` невозможно. Поэтому
MAIN-скрипт объявлен на `*://*/*` и отфильтрован по `include_globs`: он
выполняется только там, где в адресе есть подпись SDK Яндекс.Игр. Chrome при
установке всё равно предупредит про доступ ко всем сайтам — это цена за
работающую заглушку. `host_permissions` при этом остались узкими, только
`yandex.ru/games`.

Если такой размен не нужен, в `manifest.json` достаточно вернуть MAIN-скрипту
узкие `matches` — DOM-путь с таймером продолжит работать сам по себе.

Подпись SDK в адресе бывает двух видов, и ловить надо обе:

```
# игра на домене разработчика — абсолютный адрес SDK
?sdk=https%3A%2F%2Fgames.s3.yandex.net%2Fsdk%2F_%2Fv2.js&sdk_origin=sdk.games.s3.yandex.net

# игра на CDN Яндекса — относительный путь, sdk_origin отсутствует
https://app-588098.cdn.games.yandex.net/588098/…/index.html?sdk=%2Fsdk%2F_%2Fv2.js
```

Второй вариант не подходил ни под один glob, поэтому в играх с CDN Яндекса хук
не доезжал до фрейма и реклама за награду шла мимо заглушки. Диагноз читается
по отчёту: в `sdkEvents` есть запись с `detail: "top"` и нет ни одной с
`detail: "iframe"`. Теперь в списке есть и `*://*.cdn.games.yandex.net/*`, и
`*sdk=%2Fsdk%2F_%2F*`.

`sdk-hook.js` перехватывает вызовы до того, как SDK уйдёт в сеть:

- `showFullscreenAdv` → `onOpen` → `onClose(false)`;
- `showRewardedVideo` → `onOpen` → `onRewarded` → `onClose`.

Игра получает привычную последовательность событий и не зависает на «реклама
скоро закончится». Сетевая блокировка (`declarativeNetRequest`) намеренно **не**
используется: при обрыве запросов часть игр виснет в ожидании колбэка.

### Полноэкранный модал поверх игры

Часть рекламы платформа показывает сама, без участия игры, — перехватывать в SDK
нечего:

```html
<div class="play-modal adv-focusable play-modal_fullscreen play-modal_with-blur">
    <div class="play-modal__inner">…
        <button aria-label="Закрыть" class="close-button close-button_type_adv-fullscreen"
                data-testid="yandex-fullscreen-render-button"></button>
```

Просто спрятать такой модал нельзя: при `display: none` рекламный плеер не
досчитает показ, кнопка «Закрыть» не станет активной, и игра останется на паузе
за блюром. Поэтому модал **гасится через `opacity: 0`** (остаётся отрисованным)
и расширение **нажимает «Закрыть» за игрока** — каждые 250 мс, пока кнопка не
сработает. Если за 8 секунд не вышло, модал убирается принудительно.

Зацепки выбраны устойчивые: класс `adv-focusable`, `data-testid` кнопки и
формат id рекламного блока `R-A-<id>-<n>`. Хешированные классы вида
`play-yandex-wCRrBuz4aqZIJ1z3R` не используются — они меняются от сборки к
сборке. Обычные диалоги платформы (пауза, вход в аккаунт) не трогаются: модал
закрывается, только если внутри есть рекламный признак.

### Интерстишл с промо Яндекса

Между рекламой платформа показывает **собственное** промо во весь экран — «Одно
приложение вместо тысячи», «50+ топ-игр»:

```html
<div class="prowo-container prowo-container_advType_interstitial prowo-container_with-blur">
    <div class="promo-slide promo-slide_type_welcome">…
        <a data-testid="promo-button-active" target="_blank" href="/games/?utm_campaign=…">
            Играть на сайте</a>
```

`prowo-container` — через **«w»**, и это не опечатка: так слот назван в самой
разметке, чтобы не ловиться на слово «promo» в фильтрах блокировщиков.

Закрывается он тем же путём, что и рекламный модал, — `opacity: 0` плюс клик по
крестику, а не `display: none`. Контейнер держит блюр и паузу игры, и выйти из
этого состояния платформа должна сама. Список кнопок закрытия здесь **свой**:
расширять общий нельзя, широкое совпадение нажало бы не то в рекламном модале.
Ссылки исключены отдельно — внутри слайда рядом с крестиком лежит «Играть на
сайте» с `target="_blank"`, и клик по ней открыл бы вкладку.

### Фокус и клавиатура

Пока модал висит поверх игры, фокус держит он — у платформы это focus-trap,
отсюда и класс `adv-focusable`. Своим путём платформа возвращает фокус игре
сама, но этот путь расширение обходит: игра снова видна, а на клавиатуру не
реагирует.

Поэтому после каждого закрытия фокус возвращается принудительно — снимается с
перехватчика и ставится на `#game-frame`, а затем на его `contentWindow`.
Фрейм кросс-доменный, но `focus()` — один из немногих методов, разрешённых
через границу origin; без второго вызова фокус остался бы на самом элементе
`<iframe>`, а не внутри документа игры.

### Индикация

Полноэкранная реклама пропускается за доли секунды, и без индикации это
выглядит как мигание непонятно чего. В левом нижнем углу показывается плашка:

```
┌──────────────────────────┐
│ Реклама: закрываем… 3 с  │
└──────────────────────────┘
```

Счётчик появляется со второй секунды — по нему видно, что расширение работает,
а не зависло. После закрытия плашка меняет текст на «Реклама пропущена» и
гаснет через две секунды. Если крестик так и не нашёлся, честно пишет
«убрана принудительно». Большой оверлей с карточкой здесь не годится — он сам
мелькнёт и помешает; карточка с отсчётом остаётся только у рекламы за награду.

У плашки `pointer-events: none`: она висит поверх игры и не должна перехватывать
ни клики, ни фокус, который только что вернули.

### Осиротевший content-script

После перезагрузки расширения в `chrome://extensions` на уже открытых вкладках
остаётся работать **старая копия** content-script — с живыми таймерами и
наблюдателями, но с оборванным мостом в расширение. Первое же обращение к
`chrome.*` бросает:

```
Uncaught Error: Extension context invalidated.
```

Ошибка всплывает в списке расширений и выглядит как поломка, хотя лечится
перезагрузкой вкладки. У осиротевшей копии исчезает `chrome.runtime.id` — по
нему и проверяется мост, перед каждым обращением и ещё раз внутри колбэков:
контекст может оборваться между проверкой и вызовом.

Обнаружив обрыв, скрипт сворачивается тихо — гасит таймеры и наблюдателей, но
**не трогает страницу**: уже скрытая реклама остаётся скрытой, а не
возвращается игроку на глаза посреди партии.

### Зависшая оболочка рекламы

Худший из отказов: экран занят модалом, блюр наложен, игра на паузе — а внутри
пусто. Игрок видит размытую игру и одинокий крестик посреди экрана.

Так выходило, когда реклама не догружалась. Признаком показа считалось
**отрисованное содержимое**, поэтому расширение такой модал обходило стороной.
CSS при этом успевал погасить оболочку по `:has(iframe)`, и получалось худшее
из двух: рекламы не видно, а игра стоит.

Теперь признак показа разделён надвое — `isModalOnScreen()` и
`hasRenderedContent()`. Модал на экране без содержимого дольше выдержки
считается зависшим и закрывается как обычная реклама. Выдержка нужна: между
показами платформа тоже держит модал пустым, и содержимое появляется не
мгновенно. Карточка с отсчётом для зависшей оболочки не показывается — рекламы
нет, значит нет и награды, ждать нечего.

Крестик у зависшей оболочки ждать тоже нечего: если его нет сразу, он не
появится. Поэтому без крестика оболочка убирается на первом же тике, а с
крестиком — через секунду после клика, если платформа не закрыла её сама.
Раньше тут уходило восемь секунд попыток, и всё это время игра стояла.
Интерстишл с промо Яндекса считается зависшим через 1,5 секунды, а не через
2,5: слайд рисуется прямо в документе, долго его ждать не нужно.

Пустым модалом выглядит не только реклама. Меню игры, пауза и вход в аккаунт
открываются в том же контейнере платформы, и на всех стоит `adv-focusable`.
Это ловушка фокуса платформы, а не признак рекламы. Поэтому зависшей считается
только оболочка со следом рекламы: собственный крестик
(`fullscreen-render-button`, `close-button_type_adv`) или блок РСЯ (`_R-A-`).
Без этой проверки меню закрывалось само через пару секунд после открытия.

Узел модала платформа переиспользует, поэтому после закрытия рекламы наши
`opacity` и `pointer-events` снимаются. Иначе следующее окно в том же узле,
например меню, оставалось бы невидимым и не принимало клики. Модал, убранный
силой через `display: none`, держится скрытым, пока платформа не сменит ему
класс или содержимое, и только тогда получает стили обратно.

### Возврат во вкладку

Реклама всплывает и пока игрока нет на вкладке. Пока вкладка в фоне, браузер
душит таймеры: отложенный проход может не состояться, а новых мутаций к
возвращению уже не будет — разметка изменилась раньше. Модал остаётся
погашенным нашим же CSS, и игра стоит.

Поэтому проход запускается ещё и на `visibilitychange`, на `focus` окна и раз
в две секунды по таймеру. Последнее — страховка от случая, когда мутаций нет
вовсе: модал уже стоит в дереве и лишь меняет классы. Зависшая игра дороже
редкого лишнего прохода.

Фокус во вкладке в фоне не переносится. Если реклама закрылась, пока игрока не
было, фокус уходил с её кнопки в `body`, а не во фрейм: после возврата игра
была видна, но не реагировала на клавиши. Теперь возврат фокуса в таком случае
откладывается и выполняется, когда вкладка снова видна. Фокус, который
пользователь сам поставил на меню или поле ввода, не трогается.

### Припаркованные модалы

Неиспользуемые модалы платформа не удаляет, а **отодвигает за край экрана** в
полный размер:

```json
{ "class": "play-modal adv-focusable play-modal_fullscreen",
  "rect": { "x": -10200, "width": 1912, "height": 884 } }
```

Поэтому одного размера для признака показа мало — проверяется ещё пересечение с
вьюпортом. Иначе припаркованный контейнер считался бы показом: счётчик
накручивался бы на пустом месте, а через восемь секунд расширение убивало бы
узел, который платформе ещё пригодится.

### Реклама за награду

Здесь ранний клик по «Закрыть» отменяет бонус, ради которого игрок её и
запустил, поэтому политика другая. Модал гасится так же, но **вместо рекламы
показывается собственный экран с отсчётом**:

```
        ┌──────────────────────────────┐
        │  Реклама за награду скрыта   │
        │             15               │
        │  Награда придёт автоматически│
        │      [ Показать рекламу ]    │
        └──────────────────────────────┘
```

Важное условие показа: модал считается рекламным, только если внутри есть
отрисованный `<iframe>`, `<video>` или блок РСЯ с id вида `_R-A-19087429-35_2`.
Платформа держит модал смонтированным и **пустым** между показами, во всю
ширину экрана, — без этой проверки таймер всплывал сразу при запуске игры, когда
никакой рекламы ещё не было. То же условие продублировано в CSS через
`:has(iframe)`.

Отсчёт берётся из таймера самой рекламы, если платформа рисует его в документе;
иначе считается свой от 15 секунд. Как только отсчёт дошёл до нуля — бонус уже
засчитан — расширение жмёт «Закрыть» само. Кнопка «Показать рекламу» — аварийный
выход, если награда почему-то не приходит.

### Чего расширение не трогает

```html
<div id="AdBanner" class="AdsBox ad_box ad_banner ad_300x100 Ad_container"></div>
```

Элемент 1×1 за краем экрана — приманка детектора блокировщиков. Яндекс
проверяет, не скрыл ли её кто-нибудь, и требует отключить адблок. Она внесена в
`BAIT_SELECTOR` и не скрывается никогда.

Кнопки тоже под защитой: `hide()` отказывается трогать `<button>` и всё, что
внутри кнопки, — однажды широкий селектор так прибил платформенную «Отключить
рекламу». Снять предохранитель можно только адресно, флагом `allowButtons`, — им
пользуется единственное место в коде.

### Кнопка «Отключить рекламу»

Предложение убрать рекламу за деньги — рудимент, когда реклама и так убрана.
Скрывается вместе со своим слотом в разметке (`disableAdButtonSlot`,
`disableAdButtonContainer`), иначе в правом верхнем углу остаётся пустая полоса
315×32. Зацепка — `data-testid="disable-adv-button-sticky"`, классы-хеши вида
`disable-adv-button-sticky-critical-game-module__button--GrCMT` не используются.

То же предложение платформа подсовывает ещё и всплывашкой поверх игры:

```html
<div class="no-ads-popup__popup no-ads-popup no-ads-popup_type_game
            popup-module__popup--mv7Tz" data-testid="no-ads-popup-popup">
    <p class="no-ads-popup__text">Обменяйте яны на отключение рекламы…</p>
```

Она убирается через `display: none` — это промо платформы, а не рекламный показ,
досчитывать нечего. Зацепка — `no-ads-popup__popup`: этот класс стоит только на
корне попапа, у детей имена вида `no-ads-popup__content`. Хешированный
`popup-module__popup--*` не используется — он общий для всех диалогов платформы,
включая нерекламные. Перед скрытием код поднимается до внешнего узла блока,
иначе обёртка-якорь останется перехватывать клики.

Обе зацепки отключаются тумблером «Баннер в игре».

## Настройки

Иконка расширения в тулбаре:

- **Общий тумблер** — выключает расширение целиком, без перезагрузки страницы:
  инлайн-стили возвращаются к исходным.
- **Растягивать по ширине** — только на странице запущенной игры и только для
  неё. Для игр, которые держат свои пропорции и смотрятся в рамке не по центру.
- **Баннер в игре** — sticky-баннер + растягивание фрейма.
- **Полноэкранная** — и вызовы игры через SDK, и модалы, которые платформа
  показывает сама поверх игры.
- **За награду** — rewarded-ролики.
- **Каталог игр** — рекламные карточки в списках (на странице запущенной игры не
  применяется).

## Незаметность

Страница не должна узнать о расширении по его следам. Поэтому:

- **Хук SDK** в игре не оставляет ни глобальных переменных, ни меток на
  объектах SDK. Подменённые методы — это `Proxy` вокруг оригинала на том же
  месте и с тем же дескриптором: имя, длина и `typeof` совпадают. `YaGames`
  не превращается в свойство-аксессор — SDK ловится по событию загрузки
  скрипта.
- **Связь** хука с расширением — события на `document` с ничего не
  говорящими именами. Диагностика из фрейма игры идёт в отчёт через фоновый
  скрипт расширения, а не через `postMessage`, который видят скрипты
  страницы.
- **Спрятанные узлы** помнятся внутри расширения, без атрибутов в разметке.
- **Плашка и карточка награды** живут в закрытом shadow DOM: снаружи виден
  только безымянный `div`.

Отсюда же заодно исправление: тумблер «Реклама за награду» раньше не
действовал внутри игры — хук во фрейме не получал настроек. Теперь их
доставляет маленький скрипт `src/frame.js` во фрейме игры.

## Диагностика

Если баннер остался или игра не растянулась — нажать в попапе **«Скопировать
отчёт»** на проблемной странице. В буфер ляжет JSON: классы баннера, цепочка
родителей с размерами и инлайн-стилями, то же для фрейма игры, его соседи по
разметке и список «подозреваемых» — всё, у чего в классе, id или `src` есть
`adv/adfox/rtb/yabs/banner/promo`.

По этому отчёту правятся `STICKY_SELECTORS` в `src/content/config.js`.

Отдельный раздел `modals` отвечает на главный вопрос — почему модал не
обработан. В разметке «селектор промахнулся» и «признак показа не сработал»
выглядят одинаково, поэтому по каждому кандидату пишется разбор:

| Поле | О чём говорит |
|---|---|
| `kind` | `fullscreen`, `rewarded` или `promo` |
| `isModalShown` | `false` при живой рекламе на экране — промахнулся `contentSelector` |
| `contentFound` | что именно нашлось внутри и какого оно размера |
| `closeButtonFound` | нашёлся ли крестик |
| `buttons` | все кнопки внутри — видно, как платформа назвала крестик |
| `dismissing` | взялось ли расширение за этот модал |

Ещё два поля верхнего уровня: `sdkHookInFrame` — доехал ли хук до фрейма игры,
и `activeElement` — у кого фокус в момент отчёта.

Снимок разметки не показывает, что происходило минутой раньше, поэтому отчёт
несёт и историю:

| Поле | О чём говорит |
|---|---|
| `journal` | последние 120 событий: смена вкладки, начало и конец закрытия рекламы, ожидание зависшей оболочки, возврат фокуса, а также каждое изменение состояния рекламных контейнеров (`modal-state`: размер, положение, видимость, прозрачность, есть ли содержимое, что в центре экрана) и «режим окна» платформы (`platform-modal`). Время — секунды от загрузки страницы |
| `uptime` | когда снят отчёт, в тех же секундах |
| `version` | версия расширения — чтобы отличить «баг не исправлен» от «расширение не перезагружено» |
| `journal`: `wake`, `hidden-activity`, `frame-resize` | наша собственная активность: проходы по странице и их время (`scanMs`), записи стилей (`forces`), посланные `resize` (`kicks`), изменения стиля обёртки игры (`shellMutations`) и размера фрейма (`frameResizes`). `wake` — каждые 2 секунды в течение 20 секунд после возврата во вкладку, `hidden-activity` — всё, что было, пока вкладка спала |
| `sdkEvents[].t` | когда пришло событие SDK; вызовы рекламы игрой (`sdk-call`) дублируются в журнал |
| `frameMessages` | какие сообщения платформа слала во фрейм игры: тип, сколько раз, первое и последнее (секунды журнала). Показывает, стояла ли игра на паузе по команде платформы |
| `atCenter` | что лежит в центре экрана сверху вниз, с `opacity`, `pointer-events` и `z-index`. Показывает, чей крестик висит посередине и что перехватывает клики |
| `modals[].isAdShell` | `false` — пустое окно платформы (меню, пауза), закрывать его нельзя |
| `modals[].onScreen`, `stuckMs` | модал на экране и сколько он уже стоит пустым |
| `tabHidden`, `refocusPending` | вкладка в фоне и отложен ли возврат фокуса |

## Ограничения

- Игра растягивается на всю область `main.stack`, включая правые 315px. Если в
  этой колонке окажется не реклама, а нужный элемент интерфейса, фрейм его
  перекроет — тогда помогает тумблер «Растягивать по ширине».
- Как игра распорядится новым размером, расширение не решает: канвас в
  кросс-доменном фрейме недоступен. Если игра держит пропорции и стоит не по
  центру, это её собственная раскладка — лечится тем же тумблером.
- Селекторы баннера привязаны к текущей вёрстке Яндекса. На растягивание игры
  они не влияют — оно работает от структуры, а не от классов.
- Заглушка SDK ломается, если Яндекс переименует методы `adv`.
- Звук полноэкранной рекламы глушится только для медиа в самом документе. Если
  ролик играет в кросс-доменном `<iframe>`, добраться до него нельзя — звук
  будет слышен те секунды, пока модал не закроется.
- Если рекламный плеер начнёт учитывать видимость (`opacity`) при разблокировке
  кнопки «Закрыть», сработает запасной путь: через 8 секунд модал убирается
  принудительно, но игра может остаться на паузе.
- Слой SDK покрывает игры на CDN Яндекса и на домене разработчика, если в
  адресе фрейма есть подпись SDK. Игру с другой подписью хук не увидит —
  диагностируется по `sdkHookInFrame: false` в отчёте, лечится новым glob'ом.
- `div:has(...)` требует Chrome 105+.

## Разработка

Cleathernet собирается из двух частей: движка uBO Lite (скачивается при
сборке, `vendor/ubol.json`) и нашего кода — корень репозитория (слой
Яндекс.Игр, фон, хук SDK) плюс `platform/` (страница первого запуска, меню,
настройки, иконки). Всё, на что наш код опирается внутри движка, перечислено в
`dev/ubol-contract.mjs` и сверяется при каждой сборке; раз в неделю GitHub
проверяет новую версию движка и присылает pull request, если тесты зелёные.

Код для страницы пишется в `src/content/*.js`, а в расширение попадает
собранным в один файл `src/bundle/content.js` внутри замыкания — чтобы ни
одно наше имя не было общим с чужими скриптами того же изолированного мира.
Собранный файл лежит в репозитории: расширение ставится из папки без сборки.

```
cd dev
npm install                 # один раз: Playwright
node build.mjs              # после правок в src/content
npm test                    # сборка свежая + имитация Игр + проверка обновлений
npm run test:ext            # собрать Cleathernet и проверить сборку и Игры на ней
node test-detectors.mjs     # страницы-детекторы: заметно ли расширение
node test-matrix.mjs        # рядом с uBO Lite, AdBlock, ABP, AdGuard, Ghostery
```

Тестам нужен Chrome for Testing в `dev/.browsers/chrome-win64` (обычный
Chrome не загружает расширения из командной строки) и распакованные соседи
в `dev/.neighbors/<имя>`. Обе папки в `.gitignore`. Тесты не ходят на
Яндекс: страницы и SDK подставляются локально.
